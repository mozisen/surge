# 全协议用户管理与安装时选择用户

## Goal
1. 脚本支持的所有协议都纳入用户管理：一个用户可以关联多个协议，一个协议实例可以关联多个用户。独立协议能改成多用户的就改，不能改的按「一个用户一个实例」管理。确实无法管理用户的协议，安装时提示「该协议不支持用户管理」。
2. 在面板上安装协议时可以选择平台用户。

调研见 `research/protocol-user-support.md`。

## 决策记录
- D1 范围：这次只做**用户管理**。脚本里装好的全部协议都能在平台关联、管理用户、导出连接信息；面板安装仍是现有 9 种组合，但支持安装时选择用户。把面板安装扩展到全部协议另作一项。
- D2 SOCKS：**一用户一实例，按入站统计**（Xray 入站统计），配额可以生效。
- D2b Naive：**不纳入用户管理**，平台也不考虑支持。脚本保留 Naive 的安装和使用，不做改造；能力表标为 `none`，安装时提示「该协议不支持用户管理」。
- D3 ShadowTLS 组合（Snell+ShadowTLS、Snell v5+ShadowTLS、SS2022+ShadowTLS）：**一用户一实例**，凭据完全独立，停用即停服务。
- D4 平台模式下安装协议不选用户：**空实例**，之后在「用户管理」关联；脚本模式保持现状（生成 default 用户）。
- D5（已确认）SS2022 在 Xray 和 Sing-box 上都改成多用户（服务端密钥 + 每用户密钥）。只有一个与实例同密码的用户时保持原来的单密码格式，现有客户端不受影响。
- D6（已确认）「一用户一实例」的协议统一为「分配」语义：实例空着时可以分配给一个用户（生成新凭据），已有用户时只能先移除再分配。Snell 也改成这种方式，不再需要单独「安装实例后归入」。
- D7（已确认）拆成父任务加 4 个子任务：脚本能力表与多用户（含 SS2022、分配、连接信息）→ 脚本一用户一实例适配（SOCKS、Naive、ShadowTLS 组合）→ Agent → 面板。

## Requirements
- R1 每个协议有明确的用户模式：`multi`（一个实例多个用户）、`single`（一用户一实例）、`none`（不支持）。另外标明流量统计方式：按用户、按入站或端口、不统计。脚本能力声明和 inventory 上报，面板据此显示和限制。
- R2 SS2022（Xray、Sing-box）支持多用户，旧的单密码实例兼容。
- R3 SOCKS、Snell+ShadowTLS、Snell v5+ShadowTLS、SS2022+ShadowTLS 按一用户一实例管理：实例的唯一用户有凭据；到期、配额、停用时停止对应服务，恢复时重新启动；流量按入站或端口计入。
- R4 统一用户（脚本菜单和 `account_apply`）可以把用户加到任何 `multi` 实例，或分配到空的 `single` 实例；平台用户同样。
- R5 所有可管理协议的成员都能导出连接信息（新增脚本接口生成链接，凭据只在任务结果里短暂保存）。
- R6 面板安装时可以选平台用户：多用户协议在一个实例里为每个选中用户建账号；SS、Snell 为每个选中用户装一个实例。没选用户时为空实例（平台模式）。
- R7 安装时提示：脚本安装菜单和面板安装表单对 `none` 协议显示「该协议不支持用户管理」，对按入站统计的协议显示说明。
- R8 现有实例和客户端不受影响（尤其是 SS2022 单密码、现有 SOCKS/ShadowTLS 实例）：迁移只在管理员归入或分配用户时发生。

## Acceptance Criteria
- [ ] 能力表覆盖全部 22 个协议标识（Naive 为 none），每个协议的模式和统计方式都有测试
- [ ] SS2022 多用户（两个核心）与单密码兼容测试
- [ ] 一用户一实例协议：分配、到期/超额停服务、恢复启动、计数计入、移除，测试覆盖
- [ ] 平台：把同一用户关联到多个协议，同一协议关联多个用户；导出任意成员的连接信息
- [ ] 面板安装时选择用户（多用户与一用户一端口两类）
- [ ] 不支持的协议安装时提示
- [ ] 全部检查通过（CLAUDE.md），CI 通过；文档区分隔离测试与真实验收；不操作生产节点

## Out of Scope
- 面板安装其余协议（D1）
- HY2 端口跳跃、CDN、证书等协议参数的面板编辑
