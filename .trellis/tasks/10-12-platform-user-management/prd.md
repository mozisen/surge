# 平台统一用户管理

## Goal

在 Vaio Panel 中新增「平台用户」：一个用户可以绑定多个节点上的多个协议实例，由平台统一管理到期时间和流量配额。节点脚本、节点程序（Agent）和面板同步更新。

## 背景

调研结论见 `research/current-state.md`。要点如下：
- 现在的用户只存在于各节点数据库的实例里，身份是 (core, proto, 用户名)，面板没有用户表。
- 计费和到期由节点按单个实例用户执行（Agent 的 panel_quota 和本地 reconcile），没有跨节点汇总。
- Snell 和 SS 一个用户一个端口；其他协议一个实例可以有多个用户。
- 面板每个节点同时只能执行一个任务，并且要求 revision 一致。
- 脚本 `--api` 只读，没有用户写操作。

## Requirements

- R1 面板新增平台用户：用户名、备注、到期日期、流量配额、重置周期、启用状态。
- R2 平台用户可以绑定多个节点上的多个协议实例；绑定后在对应实例中创建或认领节点用户。
- R3 到期和配额由平台统一判断，按决策 D2、D3 执行停用和恢复。
- R4 用户维度的流量汇总：跨节点、跨协议的当前周期用量、剩余量和各绑定明细。
- R5 已有的实例用户可以迁移或认领为平台用户（D4）。
- R6 凭据策略按 D5。
- R7 节点离线或同步失败时状态可见，恢复后自动收敛，不重放结果未知的任务（D6）。
- R8 脚本、Agent、面板之间有能力协商；旧 Agent 和旧脚本的节点保持现有功能，不被破坏（D7）。
- R9 节点脚本能识别平台管理的用户，菜单里不能修改这些用户；`--api` 提供版本化的用户写操作，带事务、幂等、结果查询和崩溃恢复，Agent 通过它写入平台用户。
- R10 界面文案用中文，黑白简约，遵守 `.trellis/spec/frontend/component-guidelines.md`。

## 决策记录

- D2 已定：面板判断，节点兜底。面板汇总所有节点的用量，判断到期和超额后给各节点下发停用或恢复。节点保存平台下发的到期日，离线时 Agent 按到期日本地停用。跨节点配额只由面板判断。
- D3 已定：总用量达到配额后停用全部绑定；到重置周期、调高配额或管理员手动重置后自动恢复；手动停用和已到期的不自动恢复。
- D4 已定：手动认领。管理员把节点实例里的现有用户归入新的或已有的平台用户，保留凭据和已用流量；未认领的继续按实例管理。
- D5 已定：每个绑定的凭据独立；重置凭据可以针对单个绑定，也可以一次重置全部。
- D1 已定：面板新增平台用户，每个用户有自己的每月重置日（1–28，0 表示不重置），按面板所在时区的日期切换周期，所有节点共用同一个周期。
- D6 已定：离线节点上的绑定显示「待同步」，用量按最后一次快照计算，上线后自动下发最新状态；结果未知的任务仍然等人工核对，不重放。
- D7 已定：只有宣告了平台用户能力的新版节点程序才能绑定或认领；旧节点提示需要升级，原有功能不变。
- D8 已定：一个父任务加 3 个子任务（脚本 → Agent → 面板，面板包含认领和界面），按顺序实现，各自提交和验收；父任务负责跨层联调和最终文档。
- D9 已定（脚本范围）：脚本除了识别和保护平台用户，还要开放 `--api` 用户写接口，Agent 改为通过它写用户。写接口要补齐事务、幂等、结果查询和崩溃恢复。

## Acceptance Criteria（草案）

- [ ] 能创建平台用户，并绑定至少两个节点上的不同协议，各节点实际生效
- [ ] 跨节点用量合计达到配额后，所有绑定都停用；重置周期到达或调整配额后自动恢复
- [ ] 到期后所有绑定停用，延长到期后恢复
- [ ] 现有实例用户可以认领，认领时不重置凭据和用量
- [ ] 节点离线时面板显示待同步状态，恢复后自动收敛
- [ ] 旧版 Agent 节点不受影响，界面说明需要升级
- [ ] 所有检查通过（CLAUDE.md），Node 部分以 GitHub Actions 为准
- [ ] 在 docs/ 记录版本、改动、隔离测试结果和真实验收结果，两者分开写

## Out of Scope（初定）

- 面向最终用户的自助门户、订阅链接聚合、付费和计费系统
- 不操作生产节点（「香港维多利亚」），真实验收需要另行授权
