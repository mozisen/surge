# 协议安装界面 UI 优化

## Goal

面板「安装协议」流程目前是下拉框 + 一个很长的表单，观感粗糙、主要操作要滚动才能看到。目标是在不改变安装行为和提交参数的前提下，把它改成「协议卡片选择 + 分组表单」，让用户一眼看清可选协议，并快速完成必填项。

## Background

现状和代码位置见 `research/current-install-ui.md`。范围只涉及 `platform/web/app.js` 的 `install()` / `installForm()`、`platform/web/style.css` 的弹窗与安装表单样式，以及 `platform/tests/install-form.cjs`。

## Requirements

R1 协议卡片（第一步）
- 用卡片网格取代下拉框。每张卡片显示：协议名、可用内核（Xray / Sing-box / 独立核心，多内核时都列出）、简短的传输说明（如 TCP、UDP、TCP + UDP），以及该节点上已安装的同协议实例数（为 0 时不显示）。
- 点击卡片直接进入第二步，不再需要「下一步」按钮；键盘可用 Tab 聚焦卡片，Enter/空格选择。
- 节点没有可安装组合时，保持现有「暂不可安装」提示。

R2 分组表单（第二步）
- 顶部显示所选协议的说明（取代表单底部的 `#protocol-guidance`）和「返回选择协议」入口。
- 多内核协议的内核选择保留在顶部；只有一个内核时隐藏（同现状）。
- 「基础设置」：监听端口、SNI（适用协议）、用户名（适用时），始终展开。
- 「证书设置」：仅 TLS 协议（hy2、trojan、anytls）且节点支持高级参数时显示，展开。
- 「高级设置」：访问凭据、SS 加密方式、Reality 参数、Snell v6 连接设置，默认折叠，可点击展开；折叠时字段仍按现有逻辑提交（留空即由节点自动生成）。SS / SS2022 的加密方式例外，放在基础设置中，因为它决定密钥格式。
- 每个「自动生成」改为输入框右侧的紧凑按钮（文字「生成」），不再独占一行。
- 字段说明紧跟在对应字段下方；生成反馈和错误显示在底部操作区上方。
- 弹窗加宽到约 760px（现有 `.wide` 为 740px，安装弹窗单独设类），头部和底部操作区固定，只滚动中间内容；「安装实例」按钮始终可见。

R3 视觉
- 沿用现有色彩变量，黑白简约；分组用标题 + 细分隔线，不用嵌套边框；卡片悬停/聚焦有清晰边框变化。
- 窄屏（< 720px）卡片单列或双列，表单单列，无横向滚动。

R4 行为不变
- 提交给 `submitTask('install', …)` 的 `protocol`、`core`、`port` 和 params 键值与现状完全一致。
- 各字段的 hidden / disabled / required 规则、`install_options_version` 0/1/2 的分支、生成函数逻辑不变。
- 现有元素 id 保留（测试和逻辑依赖）。

## Acceptance Criteria

- [ ] AC1 打开安装弹窗看到协议卡片网格，卡片内容符合 R1；点击任一卡片进入对应表单。（R1）
- [ ] AC2 1280×860 视口下，任一协议表单的「安装实例」按钮无需滚动可见。（R2）
- [ ] AC3 表单按「基础 / 证书 / 高级」分组，高级默认折叠；生成按钮位于输入框右侧。（R2）
- [ ] AC4 375px 宽视口下卡片和表单无横向滚动、内容不重叠。（R3）
- [ ] AC5 `node tests/install-form.cjs` 通过，且覆盖卡片选择路径；提交参数断言与改动前一致。（R4）
- [ ] AC6 `node --check web/app.js`、`node tests/traffic-display.cjs`、`python -m unittest discover -s tests` 通过（本机无 Node 时以 GitHub Actions 为准并注明）。
- [ ] AC7 本地模拟节点下截图核对 VLESS、Hysteria2、SS2022、Snell v6 四个表单。

## Out of Scope

- 后端接口、Agent、脚本、安装参数语义的任何改动。
- 其他弹窗（实例管理、用户编辑、添加服务器等）的改版。
- 新增协议或新的安装参数。
- 真实节点上的安装验收（只做本地模拟节点截图）。
