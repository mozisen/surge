# 端口转发管理

## Goal
面板导航新增「端口转发」，集中查看和管理所有服务器上的端口转发规则（Realm 与 nftables 两种），与节点脚本的配置双向同步：脚本里改的平台能看到，平台改的脚本也能看到。

## 已确认
- 两种转发类型：Realm、nftables；筛选按服务器和转发类型。
- 平台支持新增、修改、启停、删除；脚本菜单补上修改和启停，两边功能一致。
- 列表显示服务状态与流量。

## Requirements
### 面板
1. 导航「节点管理」下方新增「端口转发」（`#forwards`）。
2. 列表：服务器、备注、类型（Realm / nftables）、协议（TCP / UDP / TCP+UDP）、监听（地址:端口）、目标（地址:端口）、状态（运行中 / 已停用 / 服务未运行）、流量、操作（修改、启停、删除）。离线服务器显示最后快照且不可操作。
3. 筛选：服务器、转发类型（与节点管理相同的弹出菜单），显示「筛选结果 / 总数」；支持搜索备注、端口、目标。
4. 新建 / 修改弹窗：服务器（新建可选，修改固定）、类型、备注、协议、监听地址（Realm）、监听端口（可随机生成）、目标地址、目标端口、启用。按类型限制可选项（见下）。删除需确认。
5. 规则改动作为节点任务执行，结果在任务记录中可查；不支持的旧节点提示升级。

### 规则约束
- Realm：协议 TCP / UDP / TCP+UDP；监听地址默认 0.0.0.0；目标可为域名或 IP。
- nftables：与脚本现有 nft.sh 格式兼容——始终 TCP+UDP、监听所有地址、目标必须是 IPv4；启用后开启内核 IPv4 转发。
- 监听端口在同一服务器上不得与其他转发规则或代理实例端口冲突（同协议）。

### 脚本（3.7.4-preview.9）
6. Realm 规则继续存于 `realm/rules.json`，每条补稳定 `id`；nftables 启用中的规则以 `/etc/nftables.d/port-forward.conf` 为准（nft.sh 修改的规则也能同步），备注、停用规则等元数据存于 `realm/rules.json`。
7. 「端口转发」菜单统一管理两种类型：新建（选类型）、查看、修改、启用/停用、删除、状态/日志；原 nft.sh 工具入口保留（诊断等）。
8. `--api` 新增 `forward_apply`（事务：锁、幂等、备份、执行、失败回滚）和 inventory 中的转发规则、服务状态与流量计数；能力声明 `forward_api.version=1`。

### 节点程序
9. 快照上报 `forwards`（规则、状态、流量）与 `forward_version`；执行 `forward_apply` 任务（结果未知不重放）。
