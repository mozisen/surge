# 用户管理二选一与平台一键升级节点

## Goal
1. 每台节点的用户管理只认一方：**以脚本为准**或**以平台为准**，去掉现在的双向同步和三方合并。切换到平台时清空脚本里的全部用户数据，由平台接管。
2. 节点程序和节点脚本可以在面板上一键升级，不再需要 SSH 执行命令。

调研见 `research/current-state.md`。

## 决策记录
- D1 接管方式：**直接清空**。切换到「以平台为准」时，删除节点上的全部协议用户（包括 default 用户及其凭据）、统一用户、TG 绑定、用户路由和配额/到期等用户数据；协议实例保留，但没有可用用户，现有客户端全部失效。之后由平台新建用户。
- D2 切换入口：**面板和脚本菜单都能切，可以切回**。模式保存在节点上，是唯一依据。切回脚本时，平台停止管理该节点，节点上已有的用户和凭据保留，改由脚本管理。
- D3 脚本模式下面板对用户**只读**：只显示用户和流量，不能增删改；协议实例的安装、端口、启停、卸载、导出连接仍然可用。
- D4 一键升级范围：**节点程序和节点脚本一起**升级，失败自动恢复旧版，结果显示在面板。
- D5（已确认）平台模式下面板是唯一写入方：删除三方合并、冲突提示、认领节点统一用户；节点上的统一用户只是平台用户在该节点的落地，面板始终覆盖。
- D6（已确认）旧版节点程序（不上报用户管理方式）保持现在的行为（实例弹窗可编辑用户、不能关联平台用户），升级后才进入二选一；新版节点默认「以脚本为准」。
- D7（已确认）拆成父任务加 3 个子任务：脚本 → Agent → 面板。

## Requirements
- R1 节点数据库保存用户管理方式（默认脚本）。脚本菜单、`--api`、Agent 快照都能读到。
- R2 切换到平台：先显示将删除的用户数量并强确认（面板输入节点名，脚本菜单输入 CLEAR），然后在一个事务里清空用户数据并重建配置；失败回滚。
- R3 平台模式下，脚本菜单的用户写操作全部禁用（只能查看、看分享链接、看流量、切回脚本）；面板通过「用户管理」写入，实例弹窗里的用户只读。
- R4 脚本模式下，面板不能修改用户、不能关联平台用户；Agent 拒绝面板发来的用户写任务。
- R5 切回脚本：节点保留用户，面板删除该节点的关联，平台用户的其他节点不受影响。
- R6 平台模式的同步：面板期望状态覆盖节点，不再合并节点修改。跨节点配额、到期、离线补发、未知不重放保持不变。
- R7 一键升级：面板上一个按钮，Agent 收到任务后在独立进程里下载、校验、替换节点程序和主脚本，等待新版上线，失败恢复旧版；面板显示进度和上一次升级的结果。旧版节点程序仍显示 SSH 命令（第一次需要手动升级）。
- R8 界面中文、黑白简约；所有危险操作二次确认。

## Acceptance Criteria
- [ ] 脚本：模式切换、清空用户（多用户协议、SS、Snell、旧单用户实例都没有可用凭据残留）、失败回滚、平台模式菜单锁定、切回保留用户；测试覆盖
- [ ] `--api`：`set_authority` 操作；脚本模式拒绝其他统一用户写操作；能力声明和 inventory 带上模式
- [ ] Agent：上报模式和升级能力；按模式拒绝用户写任务；升级任务在独立进程执行，成功、失败回滚、新版未上线、任务结果上报顺序都有测试
- [ ] 面板：模式显示与切换（强确认）、脚本模式只读、平台模式同步不合并、切回删除关联、一键升级按钮与结果、旧节点保持原行为；测试覆盖
- [ ] 全部检查通过（CLAUDE.md），CI 通过；文档区分隔离测试和真实验收
- [ ] 不操作「香港维多利亚」；真实验收需要另行授权

## Out of Scope
- 把脚本用户导入平台（D1 已选直接清空）
- 自动升级（无人值守定时升级）
