# 平台统一用户

> 0.3.0-preview.12 起改为「用户管理方式二选一」，见文末同名一节：下面 preview.11 中的三方合并、认领节点统一用户已删除。

本文档跟踪平台统一用户在 Agent 和面板中的实现。节点脚本部分见 `docs/script-accounts.md`，跨层设计见 `.trellis/tasks/10-12-platform-user-management/design.md`。分支 `codex/platform-3.7.4`，只推送预览分支，不创建 GitHub Release。

## Agent（子任务 3）

Agent 和面板共用版本号，随面板子任务一起升到 `0.3.0-preview.11`。

### 快照
- 新增 `accounts`：节点统一用户的全部字段（名称、备注、启停、到期、配额、重置日、周期、本周期用量、`rev`、各字段 `mtime`、平台关联与停用标记）、按脚本规则计算的状态 `state`（manual > expired > quota > platform_quota），以及每个成员的协议、端口、用户名、当前累计计数、启停和停用原因。不含任何凭据。
- 实例用户新增 `account_id`。
- 新增 `accounts_version`：只有当脚本接口的能力声明里有 `accounts_api.version == 1` 并且包含 `account_apply` 时才为 1。面板只对值为 1 的节点开放关联和同步。
- 面板的 `sanitize_snapshot` 会严格归一化这些字段：最多 1000 个统一用户，每个最多 50 个成员，合计最多 20000 个；id 必须是 uuid；名称、日期、整数、枚举格式不对的一律清空或置 0；结构错误时拒绝整个快照。

### 任务 `platform_apply`
```json
{"id":"<任务ID>","action":"platform_apply","params":{"ops":[ ... ]}}
```
- 操作格式与脚本的 `account_apply` 相同，由 `vaio/common.py:validate_platform_task` 校验，面板和 Agent 共用这一份校验。
- Agent 沿用现有的任务意图记录（指纹、结果不明时不重放）和 enforcement-pending 阻塞，用任务 ID 作为脚本的 `request_id` 调用 `account_apply`。
- 进程超时或返回 unknown 时，先调用 `result` 查询；仍然不确定就记为 unknown，等人工核对。
- 节点拒绝的情况（`rev_conflict` 会带上节点当前的版本号、账户不存在、Snell 限制等）记为 failed，这时节点上没有任何写入；`apply_failed` 表示节点已回滚。成功时只返回各统一用户的 `rev` 和是否存在。
- 脚本接口不可用（例如 Agent 使用了非默认的配置目录）时直接失败，不写入。

### 锁与结算
- 新增 `$CFG/.txn.lock`：Agent 的实例事务和 reconcile 都先拿这把锁，再拿 `.db.lock`。调用脚本 `account_apply` 时 Agent 不持有任何锁，由脚本自己拿 `.txn.lock`，避免死锁。
- reconcile（每 60 秒）会通过随 Agent 分发的脚本副本运行一次统一用户结算 `accounts_apply`（已加入 Agent 的脚本函数白名单），这样即使节点上安装的主脚本较旧，到期和合计配额也照样生效。结算失败只记日志，不影响后面的到期检查。

### 实例任务的限制
统一用户的成员协议用户：实例任务里修改配额、重置日、到期、启停，以及删除这个用户，都会被拒绝，提示去修改统一用户。重置凭据、查看连接信息、检查仍然可以单独操作。

### 测试
**隔离测试：** 新增 `tests/test_platform_users_agent.py`，共 15 项：任务校验（全部操作合法；空列表、超过 200 项、多余字段、非 uuid、未知字段、换行备注、越界重置日、布尔版本号、未知停用原因、越界端口、缺少名称、错误动作都被拒绝）；脚本接口能力解析，不认识的声明按不可用处理；写入和查询请求的结构，查询不复用任务 ID，请求 ID 必须是 uuid；响应的请求 ID 和状态都会校验；成功结果会记录，再次执行不会重放；版本冲突和已回滚的失败；超时后用查询确认结果，unknown 不重放；脚本接口不可用、待核对的自动策略会阻塞执行；实例事务持有共享锁，而 platform_apply 执行期间不持锁；实例任务拒绝修改成员的策略字段，但允许重置凭据；结算会经过脚本执行，失败不阻塞；快照里不含凭据，并带上状态、成员和 `account_id`；不可信数据会被清洗或拒绝；Agent 按脚本接口能力上报 `accounts_version`。全部 unittest 108 项通过（跳过 2 项），脚本测试全部通过。

## 面板（子任务 4，0.3.0-preview.11）

### 数据
SQLite 升到 `user_version=2`，新增三张表：`platform_users`（平台用户，包括各同步字段在面板上的修改时间 `mtime`）、`platform_links`（平台用户与某台节点上统一用户的关联：上次两边一致时的字段值 `base`、节点版本、本节点本周期用量、各成员上次的原始计数、同步状态、提示）和 `platform_pending`（显式的一次性操作，例如成员增删、重置凭据）。旧数据库和 v1 备份在启动时自动补表；备份校验接受 v2。回滚到 0.3.0-preview.10 前，需要先恢复升级前的 v1 备份。

### 同步规则
- **三方合并**：每次节点心跳，逐字段比较 `base`、节点值和面板值。只有节点改了就写回面板，并同步到其他节点；只有面板改了就给这台节点下发补丁；两边都改了而且值不同时，比较节点和面板的修改时间，以后改的为准，在关联上记录提示，并写入审计（`platform.merge`）。两边一致后更新 `base`。修改时间分别来自节点和面板的时钟，时钟偏差会影响判定。
- **跨节点用量**：按成员原始计数的增量累加到各关联；计数回落时按新计数计入一次；首次看到成员时计入当前计数（认领时保留已用流量）。周期按面板时区和用户的重置日切换，切换时清零全部关联。
- **超额停用**：总用量达到配额时，给所有节点下发 `block: quota`；周期切换、调高配额或重置用量后下发 `block: ""`。节点本地仍按自己的配额兜底。到期和启停作为同步字段下发，由节点执行。
- **调度**：每次心跳、每 30 秒的监控检查、每次管理员操作之后都会运行。只处理在线（45 秒内有心跳）、已接管、不在维护、`accounts_version=1`、没有排队中/执行中/待核对任务的节点。每台节点合并成一个 `platform_apply`，同一快照下的相同计划不会重复入队。任务记录里显示为「平台用户同步」，审计记为 system。
- **失败与未知**：节点拒绝或已回滚记为失败，关联显示「同步失败」和原因；显式操作直接丢弃，不会反复执行；其他操作 5 分钟后重新计算。版本冲突（节点同时被修改）在下一次心跳合并新快照后立即重试。结果未知时阻塞该节点，等管理员在任务记录里标记已核对后重新计算。离线节点显示「节点离线」，上线后自动补发。
- **关联与解除**：在节点新建统一用户（可以同时选择多个多用户协议实例），或认领节点上未关联的统一用户（选择设置以哪一方为准）。SS 和 Snell 一用户一端口，需要先安装实例，再在「协议」里归入。解除关联可以选择保留节点上的统一用户（改为本地管理）或一并删除；删除平台用户时，会先从所有节点解除，全部完成后再删除。

### 接口（均需要管理员会话，写操作需要 CSRF）
`GET/POST /api/users`、`GET/POST /api/users/<id>`、`POST /api/users/<id>/delete`、`POST /api/users/<id>/links`、`POST /api/users/<id>/reset-usage`、`POST /api/users/<id>/reset-credentials`、`POST /api/links/<id>/remove`、`POST /api/links/<id>/members`。

### 界面
侧栏新增「用户管理」。列表页显示状态、本周期用量（10 段计量条）、到期、节点数、同步状态，下方列出节点上未关联的统一用户，可以直接认领（旧节点显示「需升级节点」）。详情页可以编辑、重置用量、重置全部凭据、删除，并列出各关联节点的协议、同步状态、提示、本周期用量，以及每个协议成员的「连接信息」（复用现有的导出任务）。实例弹窗里，统一用户的成员会标注所属用户，编辑按钮换成「在用户管理中修改」。流量统计页底部新增「按用户 · 跨节点合计」。监控：已归入统一用户的协议用户不再逐个告警，改为按平台用户告警（80%、用尽、3 天内到期、同步失败或未知）；未关联平台的节点统一用户按节点告警。

## 0.3.0-preview.12：用户管理二选一与一键升级

### 用户管理方式
- 每台节点只认一方，保存在节点的 `meta.user_authority`，随快照上报 `user_authority`、`authority_version=1`。
- **以节点脚本为准**（新版节点缺省）：面板对用户只读。实例弹窗不显示编辑和新增用户，`create_task` 拒绝 `user_*` 任务；这台节点不能关联平台用户。
- **以平台为准**：用户只由「用户管理」写入。面板是唯一写入方，节点统一用户总是被覆盖成面板的值（删除了三方合并、冲突提示和认领）；Agent 也会拒绝发到这台节点的 `user_*` 任务。
- **切换**：节点详情 → 用户管理 → 切换。切到平台时显示将删除的用户数，必须输入节点名称；面板下发 `platform_apply {set_authority}`，节点在事务里清空用户。切回脚本后面板删除这台节点的全部关联（平台用户本身保留）；如果在节点菜单里切回，面板从快照里发现后也会删除关联。
- **旧版节点**（不上报 `authority_version`）：保持原来的行为（实例弹窗可以编辑用户，不能关联平台用户），节点详情提示升级。
- **SS 和 Snell**：先在节点上安装实例（用户名填平台用户名），再在用户详情的「协议」里归入。

### 一键升级
- 节点上报 `upgrade_version=1` 时，节点详情的升级提示显示「一键升级」：`POST /api/nodes/<id>/upgrade` 创建 `agent_upgrade` 任务（不接受参数，节点需在线、已接管、不在维护、没有未完成或待核对的任务）。
- Agent 收到任务后，在独立进程中启动升级器（systemd 用 `systemd-run --collect`、`KillMode=process`；OpenRC 用新会话），立即上报任务结果。升级器先等这次任务结果上报完成，再沿用原有流程：下载、校验、暂存自检、维护模式、替换 `/opt/vaio-agent`。同时把 `/usr/local/bin/vless-server.sh` 替换为新安装包里的 vendor 脚本（SHA-256 必须等于新包里的 `UPSTREAM_SHA`），旧脚本另存为 `.vaio-backup-<时间>`。之后等待新版上线；失败时同时恢复旧程序和旧脚本。
- 结果写入 `/var/lib/vaio-agent/last-upgrade.json`，随快照上报 `last_upgrade`，节点详情显示状态（成功、已回滚、失败）、时间和说明。
- 旧版节点程序不认识升级任务：仍显示原来的 SSH 命令，第一次需要手动升级。

### 测试（preview.12）
- 脚本：`tests/user-authority.sh`（6 组）；`tests/accounts-api.sh` 新增 set_authority 一组；`tests/accounts-cli.sh` 在 CI 中用真实进程验证切换和清空。

## 0.3.0-preview.13：全协议用户与安装时选择用户（阶段 A）

### 协议用户模式
- 节点快照的每个实例新增 `user_mode`（multi 多用户 / single 一用户一实例 / none 不支持）、`user_stats`（user / inbound / port / none）和 `user_available`（当前版本是否已经接入），与脚本 `_proto_user_mode` 的能力表一致。新版 Agent 另外上报 `share_version=2`。

## 0.3.0-preview.14：安装表单删除用户名，端口随机

- 「安装协议」表单不再显示用户名输入框和对应的「生成」按钮，所有节点类型都一样（以平台为准、以脚本为准、旧版节点）。用户名是节点上协议账号的身份标识（统计键、分享链接备注、成员定位），但不需要手填：
  - 以平台为准的节点（Agent 0.3.0-preview.13 起）安装空实例，账号名直接用平台用户名。
