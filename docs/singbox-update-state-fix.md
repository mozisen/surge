# Sing-box 统计核心更新事务修复

预览版本：`3.7.4-preview.1`。测试分支：`codex/singbox-update-state-fix`。仅发布分支，不更新 GitHub Release，不部署服务器。

修复 v3.7.3 中无业务配置时升级失败、把缺失配置误报为不兼容、下载失败仍执行停止操作的问题。

## 行为

- 仅安装核心、数据库无 Sing-box 协议且服务未运行：临时最小配置验证新核心后只更新二进制，不生成业务配置、不创建或启停服务、不安装无必要的查询工具。
- 已安装协议或服务正在运行而 `$CFG/singbox.json` 缺失：保留原核心，提示恢复配置或检查服务实际路径；不猜测其他服务配置、不用空配置覆盖业务。
- 配置存在但服务停止：校验并更新核心，保持停止；明确提示启动后再验证统计接口。
- 服务运行：备份后替换，重启并验证 API；失败恢复旧核心、配置和运行状态。
- 下载/校验阶段失败：不操作服务。配置重建或替换失败也保留/恢复旧核心。
- 使用更新锁，并在替换前确认数据库、配置、核心和服务状态未被并发修改。若进程被强制终止而遗留锁，需先确认原任务不再运行，不能盲目重试或移除锁。

## 验证

`tests/singbox-update-transaction.sh` 覆盖无协议、配置缺失、损坏数据库、非受管进程、下载/配置校验失败、停止状态保持、运行状态升级、重启/API 失败回滚、配置重建失败、安装失败、配置并发变化和锁冲突。

测试使用隔离二进制和服务模拟，不安装或启动真实 VPS 核心。平台同步修复通过 52 项隔离测试；Shell 模拟回归、语法及 diff 检查通过。需要真实统计核心的 `singbox-stats-live.sh` 本次未运行，不宣称 VPS 升级实测通过。

测试重点：无 Sing-box 协议时更新 1.14.2 应仅替换核心；配置缺失且已注册协议时应明确拒绝；原本停止的服务保持停止，下载失败不再提示无法恢复停止状态。已发布的 1.14.2 统计包下载地址不变。
