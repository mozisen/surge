# v3.7.7-preview.2

基于正式版 v3.7.6。预览版，不发布 GitHub Release。

## preview.2 更新

- **Hysteria2 可以使用其他 TCP 协议已占用的端口号。**
  - 现象：安装 Hysteria2 时输入 VLESS、Trojan 等协议已使用的端口，会提示“已被协议 X 占用”或“系统占用中”，无法继续。Hysteria2 只用 UDP，这些协议只用 TCP，实际并不冲突。
  - 原因：端口检查不区分 TCP 和 UDP。脚本内部按端口号比对所有已装协议，系统检查用 `ss -tuln` 同时查 TCP 和 UDP。
  - 修复：按协议实际使用的传输层判断冲突。
    - 只用 UDP：Hysteria2、TUIC。
    - 只用 TCP：VLESS 各模式、VMess、Trojan、AnyTLS、Snell v4、ShadowTLS 组合、Mieru。
    - 同时用 TCP 和 UDP：Shadowsocks、SOCKS5、Snell v5/v6、NaïveProxy（Caddy 会开 HTTP/3），以及未列出的协议。
  - 结果：只有两个协议用到同一种传输层时才算冲突。系统端口检查也只查本协议会用的传输层：Hysteria2 只看 UDP，TCP 协议只看 TCP。
  - 仍然冲突的组合：Hysteria2 与 TUIC 同端口、Hysteria2 与 Shadowsocks/SOCKS5 同端口。
  - 反过来，已装 Hysteria2 的端口号，现在也能给 VLESS 等 TCP 协议使用。
- **Hysteria2 新增可选的 Salamander 混淆。**
  - 安装 Hysteria2 时，在端口跳跃之后询问“是否启用 Salamander 混淆”，默认不启用。启用后输入混淆密码，直接回车自动生成。
  - 服务端：sing-box 入站加入 `obfs: {type: salamander, password: …}`。启用后客户端必须填写相同的混淆密码；流量不再像普通 HTTP/3，网页伪装会失效。
  - 混淆密码保存在协议配置的 `obfs_password` 字段。已有的 Hysteria2 节点没有这个字段，配置和输出与之前相同。
  - 客户端输出：
    - 分享链接：按 Hysteria2 官方 URI 格式，加 `&obfs=salamander&obfs-password=<密码>`。节点信息、通用订阅、用户分享链接都已加上。
    - Surge：`salamander-password=<密码>`，Surge 手册注明需要 Mac 6.4.3+，节点信息中有提示。节点信息和 Surge 订阅都已加上。
    - Loon：`salamander-password=<密码>`。
    - Clash Meta（mihomo）：`obfs: salamander`、`obfs-password: "<密码>"`。节点信息和 Clash 订阅都已加上。
  - 现有节点要启用混淆，需要重新安装 Hysteria2，或新增一个端口实例。菜单里暂时没有单独开关混淆的选项。
- **测试**：
  - 新增 `tests/hy2-udp-port.sh`。
    - Hysteria2 与 VLESS、AnyTLS、VLESS-Vision 同端口不冲突；与 TUIC、SS2022、SOCKS5 同端口仍冲突；Trojan 与 VLESS 同端口仍冲突。
    - 安装输入端口时，Hysteria2 不受只有 TCP 监听的端口影响，TCP 协议仍会提示系统占用。
  - 新增 `tests/hy2-salamander.sh`。
    - 生成的 sing-box 配置有混淆时带 salamander，无混淆时没有 `obfs`；CI 中用 sing-box 1.14.4 `check` 校验通过。
    - 检查分享链接编码，节点信息中的 Surge、Loon、Clash 行，以及 Surge、Clash、通用三种订阅；未启用混淆时不输出任何混淆参数。
  - 这两项测试依赖 bash 4+，本机 bash 3.2 跑不了，没有实际用 preview.1 脚本复现失败。按代码判断：旧的端口检查会拒绝 443，旧的 `gen_hy2_link` 忽略混淆参数，测试会失败。
  - CI 结果：[CI 45433068363](https://github.com/mozisen/surge/actions/runs/45433068363)（功能提交）和 [CI 45433482979](https://github.com/mozisen/surge/actions/runs/45433482979)（版本号提交，bash 5.2.21）：`bash -n` 通过，27 项脚本测试全部通过。
- 真实 VPS 与客户端验收：未进行。尚未实际验证 Hysteria2 与 VLESS 同端口同时运行，也未用 Surge、Loon、Clash Meta 连接启用混淆的节点。

## preview.1 新增

- **新装协议第 16 项：Mieru。** 服务端使用官方 mita（https://github.com/enfein/mieru），按官方服务端安装文档部署。
  - 安装：从 GitHub Release 下载 `mita_<版本>_linux_<amd64|arm64>.tar.gz`，走与 Xray 等核心相同的 SHA-256 校验，装到 `/usr/local/bin/mita`。官方没有 armv7 服务端，该架构会提示不支持。
  - 创建 `mita` 系统用户和组，以及 `/etc/mita`、`/var/lib/mita`、`/var/run/mita`（属主 mita，权限 775），与官方 deb 包一致。
  - 安装时询问端口、用户名和密码。端口默认随机高位端口，低于 1025 会要求重输（mita 只接受 1025-65535）。只开 TCP。
  - 配置写入 `/etc/vless-reality/mieru.json`（权限 600）：一个 TCP 端口、一个用户、`loggingLevel: WARN`、`mtu: 1400`。
  - 服务 `vless-mieru`：以 mita 用户运行 `mita run`。启动后由 root 执行 `/etc/vless-reality/mieru-apply.sh`：等守护进程就绪，`mita replace config` 导入配置，`mita stop`/`mita start` 让端口变更生效，最后确认状态为 RUNNING，失败则服务启动失败。开机或重启服务时都会重新导入，`mieru.json` 是唯一的配置来源。systemd 和 OpenRC（Alpine）都支持。
  - 属于独立协议：不支持多用户、流量统计和配额，与 Snell、NaïveProxy 相同。
- **客户端配置**：
  - 节点信息显示用户名、密码，以及 Clash Meta（mihomo）配置：`type: mieru`、`transport: TCP`、`udp: true`、`multiplexing: MULTIPLEXING_LOW`。
  - 分享链接使用 mieru 的简单分享链接：`mierus://用户名:密码@IP?mtu=1400&multiplexing=MULTIPLEXING_LOW&port=端口&profile=名称&protocol=TCP`。用户名和密码做 URL 编码，IPv6 加方括号，IPv4 和 IPv6 各一条。官方文档说明简单链接不含 socks5 端口等本地设置，mieru 官方客户端在新设备上不能单独导入，需要先有客户端配置。
  - Clash 订阅加入 Mieru 节点并列入策略组。
  - Surge、Loon、sing-box、v2rayN 不支持 Mieru，不写入 Surge 和 V2Ray 订阅，节点信息中有提示。
- **卸载**：单独卸载、重装和完整卸载都会删除 `mieru.json`、导入脚本，以及 `/etc/mita`、`/var/lib/mita`、`/var/run/mita`（mita 保存的配置里有密码）。完整卸载保留 `mita` 二进制，与其他核心相同，提示里的删除命令已加上 mita。`mita` 系统用户保留。

## 测试结果

- 新增 `tests/mieru-install.sh`（离线）：
  - 注册表和菜单：第 16 项选中 mieru，提示为 `[0-16]`，推荐随机高位端口。
  - 生成的 mita 配置内容和 600 权限。
  - 导入脚本：用假 mita 检查调用顺序为等待就绪、replace config、stop、start、status。
  - systemd unit 和 OpenRC 脚本的关键行。
  - 分享链接的编码和 IPv6 方括号，Clash 订阅节点和策略组，三处卸载清理。
  - 用该测试跑 v3.7.6 脚本会失败。
- 新增 `tests/mieru-live.sh`（真实程序，CI 中运行）：
  - 下载 mieru v3.40.0 的 mita 和 mieru 客户端，按固定 SHA-256 校验。
  - 用脚本的函数创建 mita 用户，生成配置、导入脚本和 systemd unit，再用 systemctl 启动。检查进程以 mita 用户运行、代理状态为 RUNNING、端口在监听；重启服务后仍为 RUNNING。
  - `mieru explain config` 能解析脚本生成的分享链接，解析出的用户名、密码、端口正确。
  - mieru 客户端经 mita 访问本地 HTTP 服务成功；改用错误密码则连不通。
  - mita 默认禁止访问本机地址，测试里单独给测试用户加了 `allowLoopbackIP`，脚本生成的配置没有这一项。
