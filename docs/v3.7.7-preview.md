# v3.7.7-preview.1

基于正式版 v3.7.6。预览版，不发布 GitHub Release。

## preview.1 新增

- **新装协议第 16 项：Mieru。** 服务端使用官方 mita（https://github.com/enfein/mieru），按官方服务端安装文档部署。
  - 安装：从 GitHub Release 下载 `mita_<版本>_linux_<amd64|arm64>.tar.gz`，走与 Xray 等核心相同的 SHA-256 校验，装到 `/usr/local/bin/mita`。官方没有 armv7 服务端，该架构会提示不支持。
  - 创建 `mita` 系统用户和组，以及 `/etc/mita`、`/var/lib/mita`、`/var/run/mita`（属主 mita，权限 775），与官方 deb 包一致。
  - 安装时询问端口、用户名和密码。端口默认随机高位端口，低于 1025 会要求重输（mita 只接受 1025-65535）。只开 TCP。
  - 配置写入 `/etc/vless-reality/mieru.json`（权限 600）：一个 TCP 端口、一个用户、`loggingLevel: WARN`、`mtu: 1400`。
  - 服务 `vless-mieru`：以 mita 用户运行 `mita run`。启动后由 root 执行 `/etc/vless-reality/mieru-apply.sh`：等守护进程就绪，`mita replace config` 导入配置，`mita stop`/`mita start` 让端口变更生效，最后确认状态为 RUNNING，失败则服务启动失败。开机或重启服务时都会重新导入，`mieru.json` 是唯一的配置来源。systemd 和 OpenRC（Alpine）都支持。
  - 属于独立协议：不支持多用户、流量统计和配额，与 Snell、NaïveProxy 相同。
- **客户端配置**：
  - 节点信息显示用户名、密码，以及 Clash Meta（mihomo）配置：`type: mieru`、`transport: TCP`、`udp: true`、`multiplexing: MULTIPLEXING_LOW`。
  - 分享链接使用 mieru 的简单分享链接：`mierus://用户名:密码@IP?mtu=1400&multiplexing=MULTIPLEXING_LOW&port=端口&profile=名称&protocol=TCP`。用户名和密码做 URL 编码，IPv6 加方括号，IPv4 和 IPv6 各一条。官方文档说明简单链接不含 socks5 端口等本地设置，mieru 官方客户端在新设备上不能单独导入，需要先有客户端配置。
  - Clash 订阅加入 Mieru 节点并列入策略组。
  - Surge、Loon、sing-box、v2rayN 不支持 Mieru，不写入 Surge 和 V2Ray 订阅，节点信息中有提示。
- **卸载**：单独卸载、重装和完整卸载都会删除 `mieru.json`、导入脚本，以及 `/etc/mita`、`/var/lib/mita`、`/var/run/mita`（mita 保存的配置里有密码）。完整卸载保留 `mita` 二进制，与其他核心相同，提示里的删除命令已加上 mita。`mita` 系统用户保留。

## 未包含

- 核心管理中没有加入 mita 的版本查看和更新。重装 Mieru 会沿用已安装的 mita，不会升级。
- 端口跳跃范围（portRange）、UDP 传输、多用户都未做。

## 测试结果

- 新增 `tests/mieru-install.sh`（离线）：
  - 注册表和菜单：第 16 项选中 mieru，提示为 `[0-16]`，推荐随机高位端口。
  - 生成的 mita 配置内容和 600 权限。
  - 导入脚本：用假 mita 检查调用顺序为等待就绪、replace config、stop、start、status。
  - systemd unit 和 OpenRC 脚本的关键行。
  - 分享链接的编码和 IPv6 方括号，Clash 订阅节点和策略组，三处卸载清理。
  - 用该测试跑 v3.7.6 脚本会失败。
- 新增 `tests/mieru-live.sh`（真实程序，CI 中运行）：
  - 下载 mieru v3.40.0 的 mita 和 mieru 客户端，按固定 SHA-256 校验。
  - 用脚本的函数创建 mita 用户，生成配置、导入脚本和 systemd unit，再用 systemctl 启动。检查进程以 mita 用户运行、代理状态为 RUNNING、端口在监听；重启服务后仍为 RUNNING。
  - `mieru explain config` 能解析脚本生成的分享链接，解析出的用户名、密码、端口正确。
  - mieru 客户端经 mita 访问本地 HTTP 服务成功；改用错误密码则连不通。
  - mita 默认禁止访问本机地址，测试里单独给测试用户加了 `allowLoopbackIP`，脚本生成的配置没有这一项。
- [CI 45408279941](https://github.com/mozisen/surge/actions/runs/45408279941)（bash 5.2.21）：`bash -n` 通过，25 项脚本测试全部通过。
- 真实 VPS 验收：未进行。Alpine/OpenRC 只检查了生成的脚本，没有实际运行。mihomo 客户端（Clash Meta、Clash Verge 等）也没有实际连接过。
