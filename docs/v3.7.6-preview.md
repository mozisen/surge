# v3.7.6-preview.1

基于正式版 v3.7.5。预览版，不发布 GitHub Release。

## 修复

- **安装 Xray 等核心时误报“下载包无法通过发布方 SHA-256 校验”。**
  - 现象：新机器安装 Xray 时报上述错误并拒绝安装。实际核对 Xray v26.11.9 的 `Xray-linux-64.zip`、`Xray-linux-arm64-v8a.zip`，文件与官方 digest 一致，问题不在安装包。
  - 原因：校验值只从 `api.github.com` 获取。API 限流（未登录每 IP 每小时 60 次，打开菜单时后台还会查询多个核心的版本）或网络不通时取不到校验值，脚本却按“校验失败”提示。
  - 修复：
    - API 取不到校验值时，改为读取发布页随附的校验文件（`<文件>.dgst`，以及 `.sha256`、`.sha256sum`）。这些文件从 github.com 下载地址获取，不占 API 配额。Xray 的 `.dgst` 只取其中的 SHA2-256 一行。
    - 优先级不变：内置固定值 → API digest → API 中的 checksum 资产 → 随附校验文件。
    - 提示分开：取不到校验值时提示可能是 API 限流或网络问题，并说明 `ALLOW_UNVERIFIED_DOWNLOADS=1` 的用法；校验值不一致时提示重试，不建议跳过校验。
  - 影响范围：经 `_install_binary` 安装或更新的核心（Xray、sing-box 等）都会使用回退。NaiveProxy、wgcf、cloudflared、realm 也调用同一校验函数，同样受益，但提示文字未改。

## 测试结果

- 新增 `tests/github-asset-verify.sh`：API 正常时使用 API digest、不请求 `.dgst`；API 失败或缺少 digest 时用 `.dgst` 校验通过；`.dgst` 不一致返回“不一致”；都取不到时返回“取不到”；安装入口对两种情况给出不同提示且都不安装。用这个测试跑 v3.7.5 脚本会失败。
- 本机用真实网络读取 Xray v26.11.9 两个架构的 `.dgst`，取到的值与 API digest 一致。
- GitHub Actions 结果见下方。
- 真实 VPS 验收：未进行。报错的那台机器尚未用本版重试。
