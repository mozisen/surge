# v3.7.6-preview.2

## preview.2 更新

- **增删 VLESS-Reality 或 VLESS-XHTTP 的用户后，原有 VLESS+Reality+XHTTP 连不上。**
  - 原因：添加或删除用户时，`db_add_user`/`db_del_user` 先用完整生成器重建了正确的配置；随后 `_regenerate_config` 又对 Xray 配置做局部更新，把所有 `protocol == "vless"` 的入站用户都换成当前协议的用户，并统一加上 `flow: xtls-rprx-vision`。结果 XHTTP 入站原有的 UUID 被替换，还带上了 XHTTP 不支持的 vision flow。VLESS-WS 等其他 VLESS 入站同样会被改写。删除用户、修改配额和到期等走 `_regenerate_config` 的操作也受影响。
  - 修复：Xray 用户变更一律使用完整生成器（`rebuild_and_reload_xray`），与 sing-box、SS 的处理一致。完整生成器按协议分别生成用户，只有 VLESS-Reality 和 VLESS-Vision 带 vision flow。删除了约 230 行局部更新代码。
  - 已经出问题的节点：升级到本版后，任意增删一次用户，或在菜单中重新应用配置即可恢复。
- **测试**：新增 `tests/xray-user-regenerate.sh`，在 Reality 与 Reality+XHTTP 两个 VLESS 入站并存时，分别对两个协议执行用户变更，断言另一个入站的用户和 flow 不变、并走完整重建。用该测试跑 preview.1 脚本会失败，复现结果为 XHTTP 入站被换成 VLESS 用户且带 vision flow。[CI 44926129794](https://github.com/mozisen/surge/actions/runs/44926129794)（bash 5.2.21）：`bash -n` 通过，22 项脚本测试全部通过。
- 真实 VPS 验收：未进行。

## preview.1 修复

- **安装 Xray 等核心时误报“下载包无法通过发布方 SHA-256 校验”。**
  - 现象：新机器安装 Xray 时报上述错误并拒绝安装。实际核对 Xray v26.11.9 的 `Xray-linux-64.zip`、`Xray-linux-arm64-v8a.zip`，文件与官方 digest 一致，问题不在安装包。
  - 原因：校验值只从 `api.github.com` 获取。API 限流（未登录每 IP 每小时 60 次，打开菜单时后台还会查询多个核心的版本）或网络不通时取不到校验值，脚本却按“校验失败”提示。
  - 修复：
    - API 取不到校验值时，改为读取发布页随附的校验文件（`<文件>.dgst`，以及 `.sha256`、`.sha256sum`）。这些文件从 github.com 下载地址获取，不占 API 配额。Xray 的 `.dgst` 只取其中的 SHA2-256 一行。
    - 优先级不变：内置固定值 → API digest → API 中的 checksum 资产 → 随附校验文件。
    - 提示分开：取不到校验值时提示可能是 API 限流或网络问题，并说明 `ALLOW_UNVERIFIED_DOWNLOADS=1` 的用法；校验值不一致时提示重试，不建议跳过校验。
  - 影响范围：经 `_install_binary` 安装或更新的核心（Xray、sing-box 等）都会使用回退。NaiveProxy、wgcf、cloudflared、realm 也调用同一校验函数，同样受益，但提示文字未改。

## 测试结果

- 新增 `tests/github-asset-verify.sh`：API 正常时使用 API digest、不请求 `.dgst`；API 失败或缺少 digest 时用 `.dgst` 校验通过；`.dgst` 不一致返回“不一致”；都取不到时返回“取不到”；安装入口对两种情况给出不同提示且都不安装。用这个测试跑 v3.7.5 脚本会失败。
- 本机用真实网络读取 Xray v26.11.9 两个架构的 `.dgst`，取到的值与 API digest 一致。
- [CI 43151240384](https://github.com/mozisen/surge/actions/runs/43151240384)（bash 5.2.21）：`bash -n` 通过，21 项脚本测试全部通过。
