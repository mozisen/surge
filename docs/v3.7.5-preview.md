# v3.7.5-preview.2

## preview.2 更新

- REALITY 分享链接（vless、vless-xhttp，以及外部订阅转换出的链接）增加参数 `support-x25519mlkem768=true`。mihomo v1.19.31 起会从链接读取这个参数（MetaCubeX/mihomo 提交 518c703，`common/convert/v.go`），导入分享链接即可连接 Xray ≥ 26.9.9 的 REALITY 节点，不需要 JS 覆写。v1.19.30 及更早版本不认该参数，仍需使用订阅。
- 更正 preview.1 说明：“分享链接无法携带该开关”是错的，当时只查了 `converter.go`。
- 节点信息、二维码和 base64 订阅中的链接都会带上该参数，重新生成订阅即可。安装时写入的 `.join` 文件不会自动重写，重新安装该协议后才会更新。
- 其他客户端（Xray、v2rayN 等）一般会忽略不认识的链接参数，本版未逐一实测。
- 测试：仍在维多利亚 `/tmp` 隔离运行。`bash -n` 通过；`tests/mihomo-reality-mlkem.sh` 新增分享链接断言并通过；全量结果与 preview.1 相同（新增 4 项通过，v3.7.3 上均失败；`singbox-stats-live/query/update` 3 项在 v3.7.3 上同样失败）。真实 VPS 上用分享链接导入 mihomo 的连接尚未验收。

以下为 preview.1 的内容。


基于正式版 v3.7.3。跳过 3.7.4，不包含 Vaio Panel、节点 Agent 和 po0fw 的改动。预览版，不发布 GitHub Release。

## 修复与改进

- **mihomo 连新版 Xray REALITY 超时。**
  - 原因：Xray v26.9.9 起（含 v26.10.21、v26.10.31）要求 REALITY 客户端带 X25519MLKEM768 密钥交换，而 mihomo 默认不带。
  - 修复：生成的 Clash/mihomo 订阅中，本机和外部 VLESS REALITY 节点的 `reality-opts` 增加 `support-x25519mlkem768: true`，并保留 `client-fingerprint: chrome`。
  - 分享链接自 preview.2 起也带该开关（见上文）。
- **服务器公网 IP 变化后，节点信息和配置仍是旧 IP。**
  - 新增定时任务，每 30 分钟执行一次 `vless-server.sh --check-ip`。打开一次主菜单会自动安装。
  - 确认 IP 变化后：
    - 更新数据库中保存的地址。
    - 把 `.join` 文件里的旧地址替换为新地址，包括 base64 编码的 JOIN 行。
    - 重新生成订阅文件。
    - 下次打开菜单时提示一次。没配订阅域名时，同时给出新的订阅链接，客户端需要改用新链接。
  - 防误判：IPv4 和 IPv6 分别判断。两个探测站（ip.sb、ifconfig.me）结果一致才算变化；只有一个探测站有结果，或两边不一致时，需要下一次检测得到同一地址才确认。探测失败时不做任何改动。
  - 查看节点信息、分享链接和二维码时，优先使用当前探测到的公网地址。
  - 全局 WARP、NAT 等出口 IP 不等于入口 IP 的机器，可以执行 `vless-server.sh --check-ip off` 关闭自动检测，`--check-ip on` 重新开启。
- **VLESS REALITY 从 Xray 切到 sing-box 后连不上。** 真实证书模式下，sing-box 的握手目标从 `域名:443` 改为本机 Nginx `127.0.0.1:8443`，与 Xray 一致。
- **看门狗反复重启已无配置的 `vless-reality`。** 看门狗只在确有 Xray 或 sing-box 核心协议时才守护对应服务；Snell 等使用独立服务的协议不再触发。旧版生成的看门狗脚本会在打开菜单时自动重写。

## 已知风险

- mihomo 源码注释提到，ML-KEM 在“旧版 REALITY 服务端”上可能不正常。实测 Xray 26.6.27、26.10.31 和 sing-box 1.14.3 服务端都兼容。如果外部节点使用更老的服务端，可能需要去掉该开关。
- sing-box 客户端连 Xray ≥ 26.9.9 的 REALITY 节点仍然失败，需上游修复（SagerNet/sing-box#4520），本版无法解决。
- 订阅链接没配域名时，IP 变化后客户端保存的旧订阅链接会失效，需要手动换成新链接。

## 测试结果

### 隔离测试

本机只有 bash 3.2，所以测试在维多利亚节点（Debian 13，bash 5）的 `/tmp/v375test` 临时目录中运行。所有测试都使用临时 fixture，不读写 `/etc/vless-reality`，也不重启服务。

- `bash -n vless-server.sh` 通过。
- 新增 4 项测试全部通过。用同样的测试跑 v3.7.3 原版脚本，4 项都失败，说明测试能发现这四个问题：
  - `tests/mihomo-reality-mlkem.sh`：本机与外部 REALITY 节点都输出开关和 chrome 指纹，开关位于 `reality-opts` 之下。
  - `tests/singbox-reality-handshake.sh`：
    - 真实证书模式：握手目标为 `127.0.0.1:8443`，并配置 Nginx。
    - 自签名，或 sni 与证书域名不同：握手目标为 `sni:443`。
  - `tests/watchdog-xray-filter.sh`：
    - 只有 snell-v6 时不守护 `vless-reality`；有 vless 时守护。
    - 生成的看门狗脚本语法正确。
  - `tests/public-ip-change.sh`：
    - 两个探测站结果一致时，数据库、`.join`（base64 和明文）、`join.txt`、订阅文件和菜单提示都会更新，相邻的 `2x.x.x.x` 等地址不会被误改。
    - 地址不变时不重复处理。
    - 探测失败、返回无效值或自动检测已关闭时，不做任何改动。
    - 两个探测站结果不一致时，先记录候选地址，下一次结果相同才确认。
    - 定时任务为 `*/30`；卸载时会移除。
- 原有 15 项测试：12 项通过，3 项失败。这 3 项在 v3.7.3 原版上同样失败，与本次改动无关：
  - `singbox-stats-live.sh`：需要提供统计核心二进制（`SINGBOX_TEST_BIN`）。
  - `singbox-stats-update.sh`：依赖本机服务状态，测试机上 vless-singbox 正在运行。
  - `singbox-stats-query.sh`：测试在 bash 5 的 `set -e` 下遇到 `(( updated++ ))` 从 0 自增，返回非零后退出。
