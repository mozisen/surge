# v3.7.3

## 修复与改进

- 修复用户流量超额后虽显示停用，但运行核心仍接受连接的问题；停用用户不再回退为默认凭据。
- 手动重置流量、每月自动重置后，恢复因配额停用且未到期的用户；不自动启用手动停用或到期用户。部分失败可重试，避免重复清零。
- 修复普通 Shadowsocks 密码提示误显示 SS2022；Xray / Sing-box 按端口实例写入有效用户的独立密码，与分享链接保持一致，保留默认节点密码。Sing-box 普通 SS 用户纳入流量统计。
- 修复 Telegram 用户机器人 cron 依赖检测及启动流程；先确认本地轮询就绪，再切换 webhook，失败不标记启用。支持 systemd、OpenRC 和无 init 环境，不主动解除服务屏蔽。
- cron 启动诊断保存到 `/etc/vless-reality/cron-service.log`，菜单不再显示完整 Bot Token。
- 保留主分支既有脚本模块更新；本版不包含尚在独立分支开发的平台全协议管理功能。

## 升级与验证

现有用户可在“13 检查脚本更新”中升级，或从主分支下载运行脚本。保留现有协议配置与用户数据；建议升级前备份。应用核心配置时可能短暂中断同核心的连接。

流量口径仍为用户上传与下载之和；配额按同步周期检查，并非精确到字节的实时硬限额，也不等同于整台 VPS 的计费流量。

本地 Shell 模拟回归、语法及 diff 检查通过；同步到平台固定脚本的修复通过 51 项隔离测试。未执行真实 VPS / Telegram 端到端测试；需要统计核心的 `singbox-stats-live.sh` 因未提供相应二进制未运行，不宣称实机验证通过。

若机器人仍无法启动，请查看 cron 诊断日志。曾在截图或聊天中暴露的 Bot Token 应通过 BotFather 撤销并重新生成。
